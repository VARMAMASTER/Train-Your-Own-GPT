Train Your Own GPT

A GPT-style language model built from scratch in PyTorch: our own tokenizer, transformer, training loop and fine-tuning, trained across a laptop, Google Colab and a Vultr GPU, then shipped as a public demo.

Components

What each part does

Every part has one job, clear inputs and outputs, and lives in its own folder under src/tygpt/.

Config

config.py
In
YAML file + CLI overrides
Out
Typed dataclasses

Decision: the config is saved inside every checkpoint, so every result can be reproduced exactly.

Data pipeline

data/
In
Text dir · JSONL · HF dataset
Out
Split text + data card

Decision: exact SHA-256 dedupe; split by document with a fixed seed; FineWeb is streamed, never fully loaded into memory.

Tokenizer

tokenizer/
In
Split text
Out
uint16 token shards

Decision: two backends behind one interface. Our own BPE for small runs, GPT-2 via tiktoken for the 124M run.

Model

In
Token IDs (B, T)
Out
Logits (B, T, vocab)

Decision: GPT-2 architecture, pre-LayerNorm, tied embeddings; flash attention via SDPA, checked against a manual version.

Trainer

train/trainer.py
In
Config + shards
Out
Checkpoints + metrics

Decision: AdamW, warmup + cosine, grad clipping and accumulation, bf16/fp16 picked per GPU, torch.compile.

Checkpointing

train/checkpoint.py
In
Full training state
Out
last.pt, best.pt

Decision: atomic writes (temp file + rename); saves RNG and data position so a resumed run matches an uninterrupted one exactly.

Fine-tuning

In

Out

Decision: documents → continued pretraining; conversations → SFT with loss only on assistant tokens. ~10× lower learning rate.

Generation

In
Prompt IDs

Decision: temperature, top-k, top-p; stops at end token. KV cache comes later, tested against the no-cache output.

Evaluation

Tokenizer strategy

Written from scratch, proven correct against GPT-2

ScratchBPE · ours 8,192 vocab

Byte-level BPE with GPT-2 regex pre-splitting, trained on up to ~100 MB. Used for TinyStories and custom-data experiments.

≡
Load GPT-2 merges into ScratchBPE → output must match tiktoken token for token
TiktokenGPT2 · reference 50,257 vocab

Used for the 124M FineWeb run, because a pure-Python encoder is too slow for billions of tokens.

Model

Decoder-only transformer, three sizes

PresetLayersd_modelContextParamsRuns on
tiny4128256~2MTests
small7384512~15MColab · phase 1
base124m127681,024124MVultr · phase 2

Heads = layers in every preset. Vocab is 8,192 for tiny/small and 50,304 for base124m (GPT-2's 50,257 padded to a multiple of 64). Init: normal(0, 0.02), residual projections scaled by 1/√(2·n_layer).

Environments

One codebase, three machines

Code travels through GitHub. Checkpoints travel through cloud storage. Only paths and the device change between machines.

Important: Colab can't see files on your laptop. notebooks/colab_runner.ipynb runs git clone and pip install -e ., then runs a config. Data and checkpoints live on Drive in MyDrive/mini-gpt/. The notebook is only a runner and can be rebuilt at any time.
Failure handling

What can go wrong, and what the system does about it

Colab disconnects

session ends

Resume from last.pt on Drive. At most one checkpoint interval is lost.

Loss becomes NaN

checked every step

Save a debug checkpoint, log the batch index, stop with a clear error.

Loss spike

> 3× running average

Warn. Stop if it persists over several evals.

GPU out of memory

exception on first steps

Suggest halving micro_batch_size; accumulation keeps the effective batch the same.

Vultr overspend

max_hours · max_cost_usd

Trainer saves and exits cleanly when either limit is reached.

Instance left running

human process

Teardown checklist: sync checkpoints → verify → destroy the instance.

Testing

CPU tests on every push, under two minutes

AreaWhat is checked
Tokenizerencode → decode round trip on random Unicode · ScratchBPE with GPT-2 merges matches tiktoken exactly · special tokens never split
Dataexact duplicates removed · no document appears in both train and val · uint16 shards round-trip
Modeloutput shapes · parameter count per preset · causality: changing token t+1 never changes logits at ≤ t · SDPA and manual attention agree
Trainingoverfits one batch to near-zero loss · save → resume gives the same weights as uninterrupted training · SFT mask gives zero loss from user tokens
Generationdeterministic with fixed seed · stops at the end token
